Student Management System — Java / JDBC Module (FSJP)
This is the Java 21 console application for the Student Management System. It uses JDBC and MySQL to manage student records and marks through a command-line interface, with database operations separated into model, DAO, and connection classes.
Project status: Academic/demo project. Verify the current source and database schema before relying on every feature described here.

Prerequisites
- JDK 21 or later
- MySQL Server 8.4 (or a compatible version)
- MySQL Connector/J JAR in lib/
- A configured student_management database with the required tables
Step 1 — Configure the JDBC Driver
Place the MySQL Connector/J JAR in:
fsjp/lib/
Check the actual filename in that directory. The commands below use lib/*, so they include JAR files in that folder.
Step 2 — Configure Database Credentials
If db.properties does not exist, create it from the template in PowerShell:
cd "$HOME\OneDrive\Desktop\Student-Management-System\fsjp"
Copy-Item db.properties.example db.properties
Edit db.properties using the property names expected by DBConnection.java. The typical configuration is:
db.url=jdbc:mysql://localhost:3306/student_management
db.user=your_database_user
db.password=your_database_password
Replace the example username and password with your local credentials. Do not paste credentials into chat or commit db.properties to version control. Prefer a dedicated MySQL application account instead of root.
Step 3 — Compile
Run from the fsjp directory in PowerShell:
javac -cp "lib/*" -d out (Get-ChildItem -Recurse -Filter *.java src).FullName
If compilation reports an error, copy the complete error text. Do not modify source files until the error is reviewed.
Step 4 — Run
java -cp "out;lib/*" com.studentmgmt.App
On Windows, the classpath separator is a semicolon (;).
Database Schema Notes
The current student_management schema uses these columns:
- students: id, user_id, roll_no, first_name, last_name, email, phone, course, academic_year, semester, gender, dob, address, timestamps.
- marks: id, student_id, subject1 through subject5, generated total, generated percentage, writable grade, timestamps.
- users: id, username, password, role, created_at.
Important differences from older schema examples:
- Student roll number is stored in roll_no, not roll_number.
- Student name is stored in first_name and last_name, not a single name column.
- Course is stored in course, not department.
- Academic year is stored in academic_year, not year.
- The current marks table has no semester column. Semester is stored in students.semester.
- MySQL generates total and percentage; grade is a normal writable column.
The Java code must use the actual column names above. If the source code currently uses older names, it will need a separate code update; this README does not imply those mismatches have already been fixed.
JDBC Concepts for Viva
What is JDBC?
Java Database Connectivity (JDBC) is the standard Java API for connecting to relational databases and executing SQL statements.
Typical steps:
1. Obtain a database connection with DriverManager.getConnection(...).
2. Create a PreparedStatement for parameterized SQL.
3. Execute a query or update.
4. Read query results through ResultSet.
5. Close JDBC resources, preferably with try-with-resources.
Why use PreparedStatement?
PreparedStatement allows parameterized SQL and helps prevent SQL injection when user-provided values are supplied as parameters rather than concatenated into SQL strings.
What is the DAO pattern?
The Data Access Object pattern separates database operations from user-interface and business logic. In this project, StudentDAO.java and MarksDAO.java are the database-access classes, while App.java provides the console entry point.
What are generated columns?
The current schema generates marks.total from the five subject scores and marks.percentage from their average. These generated columns should not be supplied in INSERT or UPDATE statements. The grade column is writable and is not automatically generated by the current schema.
What is a foreign key cascade?
The marks.student_id foreign key references students.id with ON DELETE CASCADE. Deleting a student removes related marks automatically at the database level.
Troubleshooting
Cannot connect to MySQL
- Confirm the MySQL service is running.
- Verify the host and port in db.properties.
- Confirm the database username and password.
- Check that student_management exists.
ClassNotFoundException: com.mysql.cj.jdbc.Driver
- Confirm a MySQL Connector/J JAR exists in lib/.
- Run the compile and launch commands from the fsjp directory.
- Ensure lib/* is included in the classpath.
SQL column not found
Compare the query with the current schema. Use roll_no, first_name, last_name, course, and academic_year; do not assume the old roll_number, name, department, or year columns exist.
Marks insert/update fails
Do not attempt to insert values into generated total or percentage columns. The current schema has no semester field in marks, and grade is writable.
